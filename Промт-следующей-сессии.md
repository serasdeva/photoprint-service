## 1. Что за проект

- Node.js 24 локально, Node 20.19+ на VPS (CI — 20/22). Express 5, EJS 7, Sequelize 6 + SQLite, JWT в httpOnly-cookie, CSRF double-submit, Helmet 8 CSP, multer 2.
- Telegram-бот (Telegraf, long polling) работает в том же процессе и с той же БД: запускается из `server.js`, поэтому инстанс всегда один.
- Публичный сайт: главная, услуги + карточка услуги, галерея, контакты, политика.
- Админка `/admin`: дашборд, услуги, галерея, заявки (список, страница, CSV), настройки сайта, настройки Telegram.
- Деплой: Ubuntu + systemd + nginx + certbot, скрипты в `deploy/`.

## 2. Состояние

### Готово и проверено

**Сессия 01.11.2026:** загрузки принимают `.jpeg` (а не только `.jpg`); редирект после ошибки CSRF не уходит на чужой домен; `mapEmbed` пускает только один `https`-iframe без inline-обработчиков; `GET /admin` ограничен 600 запросами за 15 минут; контраст бейджей и `--danger` доведён до AA; `/uploads` кешируется на 30 дней с `immutable`; добавлены E2E (11 сценариев, desktop + mobile) и ежедневные бэкапы с проверенным restore.

**Безопасность и корректность:** черновики услуг недоступны по прямому URL и не попадают в sitemap; поиск в админке по кириллице независим от регистра (`utils/search.js`); лимиты nginx 55 МБ против multer 25 МБ на файл; 500 не отдаёт `err.message` в продакшене; canonical без query + `noindex` для поиска; `robots.txt` закрывает `/admin` и `/api`; CSP без внешних CDN.

**Данные:** WAL + `busy_timeout=5000` + `synchronous=NORMAL`; миграции с реестром; индексы `(status, createdAt)` и `(telegramChatId, createdAt)`.

**Эксплуатация:** `/healthz`, graceful shutdown с таймаутом 10 с, GC файловых сессий и диалогов бота, morgan `combined` в проде, gzip и кеш в nginx (`/assets` — год, `/uploads` — 30 дней с `immutable`), деплой-скрипты собирают ассеты, делают бэкап БД и uploads, проверяют `/healthz`. Приложение слушает `HOST` (на VPS — `127.0.0.1`, наружу только nginx); `setup-vps.sh` падает, если HTTPS не поднялся, потому что без TLS `Secure`-cookie ломают формы и вход.

**Бэкапы:** `deploy/install-backup.sh` ставит `photoprint-backup.timer` (ежедневно 03:30 UTC): `sqlite3 .backup` + `PRAGMA integrity_check` + `uploads.tar.gz`, ретенция 14 запусков в `/var/backups/photoprint-service/`. Восстановление — `deploy/restore.sh <каталог>`: проверка дампа, остановка сервиса, сохранение текущих данных как `*.pre-restore-<время>`, удаление старых `-wal`/`-shm`, запуск и ожидание `/healthz`.

**Мониторинг:** `deploy/install-monitoring.sh` ставит systemd-таймер с проверкой `/healthz` раз в минуту, Telegram-алерты с дедупликацией и сообщением о восстановлении, `OnFailure=` через drop-in и лимиты journald (500 МБ / 50 МБ на файл). Chat id берётся из `ALERT_CHAT_ID`, `BOT_ADMIN_CHAT_ID` или настроек Telegram в SQLite; установка идемпотентно вызывается из `setup-vps.sh` и `update-vps.sh`.

**Сайт:** серверная пагинация галереи (12 карточек, `data-gallery-total`), догрузка и фильтры через `/api/gallery` (`offset`, `limit` ≤ 48, `category`, `q`), без JS работают обычные GET-ссылки; OG-превью 1200×630 и своя картинка у услуги; self-host Manrope и Font Awesome (168/29/10 глифов, 15,5/3,9/2,3 КБ, CSS 8,8 КБ + `icons.json` для подсказок в админке).

**Админка:** разбита на модули; заявки с фильтрами по статусу и датам, страница заявки, возврат к списку после смены статуса, CSV с BOM и экранированием.

**Изображения:** `sharp` после multer поворачивает по EXIF, ужимает до 1920 px по длинной стороне (постеры — до 1280 px) и конвертирует в WebP ~82, оригинал удаляется; битый файл отклоняется без записи в БД. Размеры хранятся в `width`/`height` (миграция `0004`) и выводятся в шаблонах, `/api/gallery` отдаёт их для догружаемых карточек.

**Зависимости:** `sqlite3` 6.0.1, `express` 5.3.0, `helmet` 8.3.0, `express-rate-limit` 8.7.2, `bcryptjs` 3.0.3, `dotenv` 18.0.9, `multer` 2.5.0 (ветка 1.x была EOL), `nodemailer` 10.3.1, `ejs` 7.0.2. ## 3. Правила работы

1. **Только запрошенный объём.** Сначала задача, потом отчёт; попутные улучшения — отдельно.
2. **Не коммить без просьбы.**
3. **Definition of done:** `npm run lint`, `npm run format:check`, `npm test` зелёные + smoke затронутых маршрутов.
4. **Язык:** интерфейс и комментарии — русский, код и имена — английский.
5. **Windows/PowerShell:** для правок — apply_patch; CRLF-файл при необходимости переводить в LF через `[IO.File]::ReadAllText`/`WriteAllText`; никогда не перезаписывать UTF-8 через `Get-Content`/`Set-Content` без явной кодировки.
6. **Секреты:** `.env` не трогать и не печатать; в отчётах маскировать.
7. **Безопасность:** не ослаблять CSP, CSRF и rate limit ради удобства.

## 6. Грабли, на которые уже наступали

- **Sequelize + SQLite:** `afterConnect` не вызывается, соединения кешируются по `uuid`, транзакция — отдельное соединение. Прагмы ставить обёрткой драйвера (`config/sqliteDriver.js`).
- **`sync()`** создаёт только отсутствующие таблицы; любые изменения схемы в проде — только через `migrations/`.
- **`sync({ alter: true })`** в development может пересоздать таблицу, поэтому индексы продублированы в модели.
- **Rate limit логина** 5/15 мин: в тестах сессия кешируется в `loginJar()`, иначе шестой вход падает.
- **Сессии в тестах** изолируются через `SESSION_DIR`, иначе тесты чистят реальные сессии разработчика.
- **Ассеты:** после правки css/js/шрифтов нужен `npm run build:assets`; без манифеста шаблоны деградируют до исходных путей (это нормально, но кеш пропадает).
- **Font Awesome:** сабсет собирается `python tools/build-fontawesome.py --src <дистрибутив FA 6.5.2>`; нужны `fonttools` и `brotli`; новую иконку добавлять в `USED_IN_APP`/`EXTRAS`, затем пересобрать и обновить `icons.json` (тест сверяет разметку с сабсетом).
- **`npm audit fix --omit=dev`** вычищает dev-зависимости (`supertest` и др.) — после него нужен `npm install`.
- **PowerShell + UTF-8** — главная причина порчи файлов; проверяй диффом, что кириллица на месте.
- **CSP:** `frame-src https:` нужен карте из настроек; `img-src` должен сохранять `data:` и `blob:` для галереи.
- **Playwright:** `webServer` переиспользует уже запущенный сервер вне CI; локально браузеры можно не качать — `E2E_CHANNEL=chrome`/`msedge`. На Windows Playwright убивает сервер без SIGTERM, поэтому временная БД в `%TEMP%` чистится при следующем запуске.
- **systemd:** в юнитах `ProtectSystem=full`, а не `strict` — при `strict` понадобился бы `ReadWritePaths` для `data/` и `public/uploads`.
- **Deploy-скрипты:** проверять `bash -n`; в песочнице на Windows/Cygwin не работают `install -m/-o` и `chown`, для локальной проверки их убирают, на Linux они нужны.
